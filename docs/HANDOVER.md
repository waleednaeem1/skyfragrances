## 1. Credentials the owner creates or sets

| Credential | Created where | Entered where | Stored where |
|---|---|---|---|
| Hostinger login | hostinger.com | hPanel only | — |
| MySQL database name, user, password | hPanel → Databases → Management | Installer screen 2 | `public_html/config.php` → `db` |
| `orders@skyfragrances.com` mailbox password | hPanel → Emails | Installer screen 2 (optional) | `config.php` → `smtp.pass` |
| Admin username + password (12+ chars) | Installer screen 3 | `/admin/login` | `admin_users.password_hash` (bcrypt) |
| Install key (32 hex) | Written by the installer to `storage/.install-key` | Installer screen 2, once | Deleted when the install finishes |

| Maintenance preview key | Generated by the installer; regenerable | Typed on the closed page | `settings.maintenance_bypass` |
| Google Search Console verification | Google | Settings → SEO | `settings.google_verification` |

`config.php` is written once by the installer and set to mode `0400`. Nothing on the site ever
rewrites it. Changing the mailbox password means editing it by hand (guide, Part 10).

There is **no** password-reset email. Recovery is `app/tools/reset-password.php` (register C-64):
the owner copies it to `public_html/` in File Manager, opens it, creates the empty nonce file
`storage/reset-{16hex}` it names, and sets a new 12+ character password; the tool clears
`admin_login_attempts` for the account, deletes the nonce, its pending file and itself, and only
the browser that started the flow can finish it (cookie-bound, one hour). Guide Part 10 →
"Forgotten admin password" carries the steps; the phpMyAdmin hash paste stays there as the
fallback. Exercised over HTTP on 2026-09-29 (§8b).

## 5. Known limitations and deliberate decisions

1. **Password recovery is a File-Manager tool, not an email.** `app/tools/reset-password.php`
   (C-64) ships in the denied `app/` tree and must be copied to the root to run; it proves
   File-Manager access with a nonce file before showing the form and removes itself afterwards.
   The Tools page and the login page point at the guide's "Forgotten admin password" section.
2. **Home page product rows need ≥ 4 live perfumes.** `app/controllers/home.php` hides best
   sellers / new arrivals / for-whom rows when fewer than four active products exist and shows
   an "empty" hero instead. `/shop` lists everything regardless. The guide tells the owner to add
   perfumes before removing the samples.
3. **`install.php` self-deletes only on a production host.** On a local/dev address the
   installer keeps the file and shows the red "Delete install.php now" panel with a delete
   button. On skyfragrances.com it deletes itself (green panel).
4. **`sitemap.xml` returns 404 while `site_indexable = 0`.** The installer sets it to 0 on any
   host other than skyfragrances.com. On the real domain it is 1 from the start.
5. **Emails without SMTP.** If no mailbox is entered, emails are written to
   `storage/logs/mail-preview/` and queued in `email_outbox` with nothing sending them. Adding
   SMTP later is a `config.php` edit (guide, Part 10).
6. **No cron by default.** Order emails go out when an admin page is loaded (≤ 2 per load). A
   15-minute cron on `cron.php` is optional and needs the `cron_key` from `config.php` when
   called over HTTP; from the CLI it needs no key.
7. **Admin sessions are bound to the browser (user-agent).** A different browser = log in
   again. There is one admin account; no roles.
8. **Lock-outs:** 5 wrong passwords per username add a delay; 10 per IP return 429 for 15
   minutes. Cleared by time or by emptying `admin_login_attempts`.
9. **HSTS is off** (Q-23). One `.htaccess` line for a developer to add once the certificate has
   been stable for a while.
10. **Sub-folder installs are not supported** (C-71). The installer refuses unless the files are
    at the domain root.
11. **hPanel "Force HTTPS" must stay off** — the site does the redirect itself; Hostinger's
    switch prepends a competing rule.
12. **Update ZIPs re-ship `install.php`, `.htaccess`, `robots.txt` and the sample images.**
    After extracting an update the owner must delete `install.php` again and re-press "Make HTTPS
    permanent" (the shipped `.htaccess` has the 302 line). Sample image files re-appear under
    `uploads/products/sample/` as harmless orphans if the sample rows were removed. A developer
    can trim update ZIPs to avoid this.
13. **`.user.ini` sets `session.cookie_secure = 1`** — correct on the live https domain; on a
    plain-http local copy served by Apache/LiteSpeed the admin login would not stick. The
    PHP built-in server ignores `.user.ini`, so local testing with `php -S` is unaffected.
14. **Orders are never hard-deleted** from the panel; cancellation is the terminal state.
15. **Reviews** are customer-submitted and admin-approved only; the 8 seeded ones are unapproved
    and are removed with the sample data.
16. **Payment proofs** are re-encoded to JPEG and stored under `storage/proofs/YYYY/MM/`, served
    only through the admin (`/admin/orders/{n}/proof`).

## 6. The `motion-wip` branch

`main` is the launch build: storefront, commerce engine, intro loader (`assets/js/intro.js`),
admin panel. `motion-wip` holds an unfinished scroll-driven motion layer — `core.js`,
`motion.css` and per-section modules — that was removed from `main` before launch because it was
not stable. Nothing on `main` references those files (verified by grep over the shipped tree).
When it is finished it should be merged as a separate release with its own smoke run; the ZIP
manifest (`site/dev/zip-manifest.php`) will need the new asset paths added to `required_files`.
